## Proven Correction

The Build 0303 six-byte insertion at `arcade_pc 0x00050482` shifted the retained
pass-sequence table from its previous relocated address. Exact current
`address_map.json` mapping places `arcade_rom/data 0x00050F6B` at
`runtime_data 0x00051171`.

Builds 0303 through 0305 retained the previous explicit data immediate
`runtime_data 0x0005116B`. That location contains byte `0x95`; the correct table source
at `runtime_data 0x00051171` contains byte `0x00`. Descriptor rebuild consequently wrote
the wrong pass selector to `Genesis-WRAM 0x00FF10A8` and selected the collision row
producer instead of the selector-0 column producer.

The sole causal remap change is:

```text
arcade_pc:        0x0503CE
original bytes:  203C00050F6B
old replacement: 203C0005116B
new replacement: 203C00051171
```

The generated Build 0306 instruction at
`runtime_genesis_pc 0x000505CE` is:

```asm
move.l #0x00051171,d0
```

Generated bytes are exactly `20 3C 00 05 11 71`. The generated patch manifest records
`arcade_pc 0x000503CE`, `rom_pc/runtime_genesis_pc 0x000505CE`, and replacement
`203c00051171`. The stale address remains ordinary ROM data but is no longer referenced by
this remap.

This is a data-pointer correction. It does not force selector zero, patch collision data,
change collision classification, change terrain tables, or modify a collision consumer.

selector-0 column behavior established for Build 0302. The nonzero-row candidate at
`runtime_genesis_pc 0x00070638` did not become the first writer.
