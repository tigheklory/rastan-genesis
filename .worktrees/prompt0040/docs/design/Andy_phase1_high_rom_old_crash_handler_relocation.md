## OLD CRASH-HANDLER LOW-ROM OWNERSHIP
**PROVEN.** `crash_handler.s` used `.section .text.boot`, so it linked into the low `.text.boot` output section
(0x0) right after boot.s (vectors 0x0–0x3FF + boot code to 0x3A4), ending at `genesistan_crash_handler_end` = 0x117E.
`postpatch_startup_rom.py` (line ~1475) computes `preserve_low_rom_end = max(0x400,
genesistan_crash_handler_end)` and splices the arcade copy there. **That is exactly why enlarging the handler
(Builds 0288–0291) pushed the arcade splice 0x117E → 0x125C: the arcade base *follows* the handler's end.**

## HIGH-ROM CRASH-SECTION DESIGN
**PROVEN.** New linker output section **`.crash`**, placed AFTER `.text.wrapper` (all Genesis-only code). The section
name is `.crash` (not `.text.crash`) specifically so `.text.wrapper`'s greedy `*(.text .text.*)` glob cannot capture
it — an initial `.text.crash` attempt was globbed into the wrapper and shifted `z80_driver_start` 0x18492C→0x185704;
renaming to `.crash` fixed that (z80_driver back to 0x18492C). `crash_handler.s` now uses `.section .crash`.

## LINKER PLACEMENT
**PROVEN.** `link.ld`:
- `genesistan_crash_handler_end = 0x0000117E;` is **pinned** (absolute) so the postpatch keeps the arcade splice at
  the Build0292 value regardless of the handler's real size/location. The freed low area 0x3A4–0x117E becomes objcopy
  zero-fill.
- `. = ALIGN(0x1000); .crash : { *(.crash) }` after `.text.wrapper` — the linker computes the address (0x185000),
  not a hard-coded historical address. Future handler growth extends only the high ROM end.
Resulting symbols (clean rebuild): `genesistan_crash_handler_end`=0x117E, `_vblank_service`=0x700C2,
`z80_driver_start`=0x18492C (all unchanged), `_crash_stub_bus_error`=0x185000, `_crash_common`=0x1850A2 (high).
