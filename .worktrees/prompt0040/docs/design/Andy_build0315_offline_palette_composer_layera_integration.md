# Andy — Build 0315 Offline Palette Composer Layer-A Integration (retrospective)

**Type:** implementation/verification. EXTENDING. This report repairs the omission of a required design
doc for Build 0315. It does not overstate what 0315 achieved.

## 1. Frozen input
`build/rastan-direct/build0314/Test.snapshot.json`, SHA-256
`deb696452d7456b323fd4cadfa982a40a57ccf7eb5997f9e750c511f0a82df0c`. Context `context:gameplay.r01.p01`.

## 2. Purpose
First attempt to put the editor-authored R1/P1 Layer-A palette/index policy into a real ROM so Tighe could
visually test the Palette Composer. Layer-A only; sprites out of scope.

## 3. Offline compiler functionality added
- `tools/graphics_editor/compile_editor_layera.py`: applies each usage's `index_map` to the source tile
  pixels → final Genesis 4bpp bytes; emits `line3_cram.bin`, `layera_patterns.bin`, `manifest.json`.
  Proven: Line-3 CRAM == editor exactly; sample tiles reindexed; 1576 usages → 1365 unique patterns.
- `tools/graphics_editor/gen_reindexed_region.py`: build-stage generator of
  `build/regions/pc080sn_editor_layera.bin` — a copy of the arcade region with **only** Layer-A tile codes
  reindexed. The raw `build/regions/pc080sn.bin` is never modified. Layer-B codes are disjoint (proven: 0
  shared) so Layer B is untouched.

## 4. Exact Line-3 palette generated (entries 1..15)
`028C 044C 0026 0004 0002 0424 0624 0402 0202 0200 0422 0440 0660 0AA6 0884` — verbatim from the editor.

## 5. Production path that DID receive transformed graphics
`scene_load.s` `genesistan_pc080sn_tile_rom` incbin was redirected to the reindexed region, and
`palette_hooks.s` was changed so the FG carrier stages the static `editor_layera_palette` (the exact 15
words) onto the Layer-A CRAM line. Static proofs: 0315 differs from 0314 by 622,903 bytes; the editor
palette is embedded at ROM offset 0x804D8 (absent in 0314); a reindexed tile is present in the ROM.

## 6. Gameplay path that DID NOT
Gameplay Layer-A tile **patterns** are DMA'd from `boundary_packages.bin`, generated by
`compile_pc080sn_genesis.py` from the **raw** region — a path 0315 did not reindex. So in gameplay the tiles
were still raw-indexed while the CRAM held the editor palette → indices displayed through the wrong entries.

## 7. Why 0315 was only partial
The transformed patterns reached the `scene_load` path, not the gameplay boundary-package path. Result: the
editor palette family appeared on Layer A, but cave/interior and water/waterfall looked wrong because their
pixel indices were not remapped in the gameplay path (Tighe's observed result).

## 8. Code-indexed region limitation
A code-indexed region holds one 32-byte value per tile code. It cannot represent the same code under two
source banks producing two different reindexed patterns — so it forced a per-code ("dominant") choice for
the multi-map codes. Acceptable only because 0315 was explicitly partial.

## 9. Multi-map finding
1576 logical usages; 1314 distinct tile codes; **64 codes carry more than one editor index_map**; all
resolved by `(tile_code, source_palette_bank)` — `(code,bank)` yields 1576 unique keys with **0 conflicts**.

## 10. Canonical registry status
`specs/palette_decisions.json` was NOT changed for 0315 (unchanged pre/post). The editor realization is a
candidate, not promoted production policy.
