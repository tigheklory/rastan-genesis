## First causal divergence

Static source data is present. Records 16–20 contain 283 legal source codes representing 282 exact
patterns, with zero drops, and fit the existing 676-slot Plane-A allocation. Build 0373 instead
generated:

- `FG_BOUNDARY_RECORDS = 16`;
- no record entries for 16–20;
- no Phase-2 residency package.

At runtime the Build-0373 `_c` trace reached stable Phase 2 at progression `0x11`, selector `1`,
strip `0`, group `0`. The native producer miss counter rose from `64` on entry to `3648`, proving
that source cells were being consumed but did not resolve through the active LUT. When record 17
was selected, `fg_boundary_install` took its `record >= FG_BOUNDARY_RECORDS` disable branch and set
both active record and package to `0xFFFF`.

This is the first broken contract: **RESIDENCY_SELECTION**. It precedes dirty publication, VBlank,
VRAM, and display.

## Remaining dependency discovered by validation

Record 16 is a scene-reseed record. Current code defers residency installation until scene-fill
completion even though the current generated record table has one variant for every record and the
installer explicitly forces variant zero. Consequently the scene-fill producers run before package
5 becomes active, record 3,648 misses, and write blank tile indices. The later package installation
cannot reconstruct those lost semantic cells; it only remaps names already present.

The corrected general contract is therefore likely to make package 5 resident before the record-16
scene fill (or otherwise replay that semantic fill after installation). That ordering change was
not built because the task authorized at most one numbered test build and Build 0374 had already
been produced and preserved. Build 0374 must not be overwritten or called accepted.
