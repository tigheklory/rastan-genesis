Method & caveats

What this benchmark measures, and how to read it
  1. Route: coin → start → hold Right → first rope attachment (Segment 2). Frame count from first controllable frame to the deterministic rope-attach state transition. Stock MAME invincibility cheat only prevents enemy-contact disruption of the Right-only route; AI, collision lookup, velocity, camera, scrolling, timers and rope logic all still run.
  2. Arcade Silver Standard = 771 frames / 12,850.000 ms (Rastan World Rev 1). Lower = faster.
  3. Determinism: most builds produce three identical trial frame counts; values here are the medians.
  4. Global route, not exhaustive coverage: a local optimization produces NO rope change if the Right→rope route never exercises it — e.g. 0425 (Plane-A selector 1/2), 0433 (death effects), 0434 (vertical rows). No rope change ≠ the optimization did nothing.
  5. Correctness ≠ speed: fast benchmarkable builds can be rejected on real hardware — e.g. 0415 and 0421. Rejected builds are shown but visually distinct; do not read them as accepted milestones.
  6. Data correction: the initial parallel historical sweep exposed a shared-resource/concurrency issue in the orchestration wrapper that produced false BENCHMARK_ERROR entries for several otherwise-good ROMs. Those builds (0412–0419, 0421) were rerun sequentially (--jobs 1 --force); the corrected deterministic PASS values are used here. The ROMs themselves were not defective.
  7. Causation: a 1–2-frame change between adjacent builds is not treated as causal without corroborating report evidence; annotations are tagged by evidence strength.
